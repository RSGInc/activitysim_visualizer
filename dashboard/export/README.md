# Offline HTML Export

This package builds the standalone HTML export used for offline dashboard sharing.

The design goal is deliberately modest: Python prepares a JSON payload, embeds that
payload into one HTML file with CSS and Plotly, and a small browser runtime renders
the result. This is not a frontend application with a separate deployment model.

## Data Flow

1. Python builds an `ExportPayload`.
2. Python serializes supported Panel objects into export nodes.
3. Python embeds the payload, CSS, Plotly, and runtime JavaScript into one HTML shell.
4. The browser runtime validates the payload schema version.
5. The runtime renders the page tree, page-local selectors, region variants, and Plotly figures.

## Important Files

- `payload.py`
  Builds page descriptors, dashboard states, selector metadata, and region variants.
- `serializer.py`
  Converts supported Panel objects into export nodes and sanitizes JSON-unsafe values.
- `types.py`
  Defines the Python-side payload and node shapes, including `EXPORT_SCHEMA_VERSION`.
- `runtime_assets.py`
  Loads CSS and the generated runtime asset, then assembles the final HTML shell.
- `html.py`
  Public entry points for building and writing the self-contained export document.
- `assets/export_runtime.js`
  Generated browser runtime shipped inside exported HTML files.
- `js_runtime/`
  Readable runtime source files that are concatenated into `assets/export_runtime.js`.
- `build_export_runtime.py`
  Concatenates `js_runtime/` into `assets/export_runtime.js`.
  Rebuilds the generated runtime asset from `js_runtime/`.

## Runtime Source Layout

The generated runtime is intentionally split into small files so Python-oriented
developers can change one concern at a time:

- `schema.js`
  Payload parsing and top-level schema checks.
- `state.js`
  Pure state helpers such as page lookup, active child resolution, and selector state updates.
- `dom.js`
  Small DOM helper functions. These are intentionally simple helpers, not a framework.
- `plotly_lifecycle.js`
  Plotly rendering, resize retries, and `ResizeObserver` handling.
- `renderers/`
  Node renderers and app-shell rendering.
- `errors.js`
  Typed runtime errors with stable error codes.
- `debug.js`
  Optional debug logging and payload summaries.

## Python-to-JavaScript Contract

The contract is versioned by `EXPORT_SCHEMA_VERSION` in `types.py`.

When you change payload structure:

1. Update `types.py`.
2. Update the Python payload builder in `payload.py`.
3. Update the runtime source in `js_runtime/`.
4. Rebuild `assets/export_runtime.js`.
5. Update fixture payloads in `tests/fixtures/`.
6. Update contract and smoke tests.
7. Bump `EXPORT_SCHEMA_VERSION` if the runtime can no longer safely read older payloads.

The contract reference lives in [`docs/export_html_schema.md`](../../docs/export_html_schema.md).

## Trusted HTML Boundary

HTML nodes are rendered with `innerHTML` in the browser runtime.

That is only acceptable because those nodes come from dashboard-owned Python
serializers such as `pn.pane.Markdown`, `pn.pane.HTML`, and explicit string output
generated by this repository. The export runtime must not be treated as a safe
renderer for arbitrary untrusted user HTML.

If you are changing HTML node behavior, document the trust assumption and keep the
boundary explicit in both Python and JavaScript code.

## Region Serialization Safety

Region export works by temporarily mutating selector widget values so each selector
combination can be rendered and serialized. That mutation is isolated in
`payload.temporary_widget_values(...)` so widget state is restored on both success
and failure paths.

If you touch selector-driven region export:

- keep widget mutation scoped
- restore original widget values in `finally`
- keep tests for both success and exception paths

## Debugging Exports

When an export looks wrong:

1. Open the exported HTML file in a browser.
2. Open developer tools and check the console.
3. Look for `ExportRuntimeError` messages and error codes.
4. Enable debug logging with `?debug_export=1`, `localStorage.debug_export = "1"`, or `payload.debug = true`.
5. Compare the embedded payload against fixture payloads in `tests/fixtures/`.

## Adding a New Node Kind

1. Add the new typed node shape in `types.py`.
2. Emit it from `serializer.py`.
3. Add a renderer in `js_runtime/renderers/`.
4. Register it in the node renderer registry.
5. Rebuild the runtime asset.
6. Add serializer, contract, and smoke coverage.
